# e2e_smoke 追加 module0.5 真实链路验证 设计

> **状态**：设计定稿，待评审。
> **范围**：在 `scripts/e2e_smoke.py`（现止于 module3）末尾追加一段 module0.5 真实链路验证，用真实 gpt-5.5 + 真实 Qwen embedding + 真实 Judge 跑通 ①②③④ 闭环。**仅改脚本，零 src 改动。**
> **目标**：V1 上线检测——验证 module0.5 的三个"真实 LLM/embedding 依赖点"（① 提议格式、② embedding 阈值、④ judge 回填质量）在真实组件下按接口约定行事，这三处离线测试全部用假数据绕过了。

---

## 1. 背景与动机

module0.5 有完整离线闭环测试（`tests/module0_5/test_evolution_e2e.py`），但它用 FakeEmbedder + 手构造向量 + FakeJudge，绕过了三个真实依赖点：

| 依赖点 | 离线测试 | 真实 e2e 能验 |
|--------|---------|--------------|
| ① 真实 gpt-5.5 是否按新 prompt 吐 `label_proposals` | ❌ 假响应 | ✅ |
| ② 去重/挂载阈值 0.85/0.6 在真实 Qwen embedding 下是否合理 | ❌ 手构造向量 | ✅ |
| ④ 真实 Judge 判"切片是否演示新能力"的质量 | ❌ FakeJudge 脚本 | ✅ |

主链路真实 e2e 刚暴露过同类风险（`min_turns`：真实 LLM 生成的东西与假设不符），所以对同样依赖真实 LLM 行为的 0.5 ①，验一次有实际价值。

## 2. 已确认决策

| # | 决策点 | 选定 |
|---|--------|------|
| 1 | 放置形态 | 追加到现有 `e2e_smoke.py` 末尾（module3 之后），复用同一次 compiler 的 `label_proposals` |
| 2 | ① 触发策略 | **真实尽力 + 注入兜底**：真实提议非空则用之；否则注入兜底 LabelProposal，保证 ②③④ 一定被真实 embedding+judge 验到 |
| 3 | ④ 回填标签 | 选一个"现有语料真实存在、v0 词表未精确收录"的新能力 → `fix_runtime_exception`，让 ④ 真命中，展示 ③→④ 完整升权闭环 |

## 3. 兜底新标签的选择依据

`smoke_20.jsonl` 含 6 条**运行时错误修复**轨迹：smoke_008(TypeError)、009(KeyError)、013(ImportError)、015(FileNotFoundError)、018(ValueError)、020(RuntimeError)。

v0 词表 `error_recovery` 家族只有泛化的 `effective_error_fix`，**无专门的运行时异常修复标签**。故兜底标签：

```python
LabelProposal(
    label="fix_runtime_exception",
    description="修复运行时抛出的异常，如 TypeError/KeyError/ValueError",
    parent="error_recovery",
    description_embedding=<emb.embed(description) — 真实 Qwen>,
    keywords=["TypeError", "KeyError", "ValueError", "Traceback", "RuntimeError"],
    source_sub_problem_id="e2e_injected",
)
```

- **v0 未收录** → ① 有理由提议 / 兜底注入合理。
- **与语料相关** → ④ 真实 judge 能在那 6 条运行时错误轨迹上命中。
- **挂 error_recovery** → ② 应判 new_leaf（挂已有父）。

## 4. 数据流（追加在 module3 输出之后）

```
【① 提议捕获 — 真实,尽力而为】
  读主链路那次的 compiler.label_proposals（gpt-5.5 编译时产出）
  打印:本次 module0 是否提议了新标签及其内容
      ↓
【选定新标签】
  proposal = 真实提议[0]  IF compiler.label_proposals 非空
           ELSE 兜底 LabelProposal(fix_runtime_exception,
                description_embedding=emb.embed(其 description))
  打印:用的是"真实提议"还是"兜底注入"
      ↓
【② 去重+挂载入库 — 真实 embedding】
  store = TaxonomyStore(taxonomy)          # taxonomy 是主链路已加载的 v0
  # 若走兜底路径,proposal.description_embedding 已由 emb.embed 填充(真实向量);
  # 若走真实提议路径,其 embedding 已由 compiler 用同一 embedding_model 算好。
  res = ingest_proposal(proposal, store, created_at="2026-07-10T00:00:00Z")
  打印:res.kind、挂载父节点、入库后 taxonomy version
      ↓
【③ 回填前:继承降权兜底 — 真实召回】
  hits = pipeline._store.recall(
      structured_filters={}, keywords=proposal.keywords,
      query_embeddings=[proposal.description_embedding], top_n=cfg.recall_top_n)
  before = rerank_with_inheritance(hits, target_label=proposal.label,
                                   taxonomy=store.snapshot())
  打印:top 几条的权重(标了父 error_recovery / 兄弟 effective_error_fix 的应 ×0.3;
        无精确命中)
      ↓
【④ 异步回填 — 真实 judge】
  new_label = store.snapshot().get(proposal.label)
  bf = await run_backfill(new_label, pipeline._store, pipeline._judge)
  打印:BackfillResult(candidates_screened / judged_true / slices_written / errors)
      ↓
【③ 回填后:精确升权 — 对比】
  hits2 = pipeline._store.recall(...同上...)
  after = rerank_with_inheritance(hits2, target_label=proposal.label,
                                  taxonomy=store.snapshot())
  打印:被回填的切片现在 ×1.0(从 ×0.3 升上来)——展示 ③ 与 ④ 是同一打分逻辑两时间点
```

## 5. 关键设计点

- **judge 复用**：④ 用 `pipeline._judge`（module1 已构造的真实 Judge，同 gateway/同 gpt-5.5），不新建。
- **embedding 复用**：主链路已加载 `emb`（EmbeddingModel）；兜底标签的 description embedding 用 `emb.embed(...)`，与 ② 去重/挂载所需向量同模型同维度（契约 §6）。
- **taxonomy 复用**：`TaxonomyStore(taxonomy)` 包主链路已加载的 v0 taxonomy。回填是对内存 `pipeline._store`（含 20 条 smoke 签名）跑，跑完即弃（脚本级，不落盘）。
- **时间戳注入**：`ingest_proposal(created_at=...)` 传固定字符串（纯逻辑不产生时间的既有约定）。
- **① 真实性如实报告**：无论 gpt-5.5 是否提议，都打印实际情况——这正是本次要观测的"真实 LLM 是否按 0.5 接口约定行事"。
- **零 src 改动**：仅 e2e_smoke.py 追加一段，复用现有 0.5 API（ingest_proposal / run_backfill / rerank_with_inheritance）+ module1 store/judge/emb。

## 6. 成功标准

- 脚本跑通不崩。
- ② `ingest_proposal` 产出 `new_leaf`，挂在 `error_recovery` 下。
- ④ `run_backfill` 的 `judged_true ≥ 1`（真实 judge 在运行时错误轨迹上命中）。
- ③ 回填后至少一条切片的权重从继承（×0.3 或无精确命中）升到精确 ×1.0。
- 如实打印 ① 真实提议情况（有/无、内容）。
