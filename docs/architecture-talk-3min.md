# SWE 轨迹优选器 — 3 分钟讲稿(技术评审版)

> 面向技术评审,配合 `docs/diagrams/architecture.png` 讲。
> 约 700 字,3 分钟。重心在**设计决策与权衡**,不做概念科普。

---

## ① 问题定义与约束(约 30 秒)

目标:从海量回流 SWE Agent 轨迹里,筛出高价值 SFT 样本,让模型 A 补齐用户反馈里的能力短板。

三条硬约束决定了整个架构:**一、输入端只有自然语言问题清单,没有配对的失败样本**——所以这是个冷启动的检索问题,不是分类问题;**二、轨迹超长(几万到十几万 token)**,切片是必须的,而切片本身就是 SFT 的候选单位;**三、不维护 test case 和程序化检测器**。但轨迹里环境返回的 stdout/stderr/exit code 是**免费的自报信号**,这是我们后面很多设计的支点。

## ② 贯穿全局的核心设计:失败→能力的翻转(约 25 秒)

一个决定性认知:**查询描述的是"失败",要检索的是"正确能力",中间必须做一次翻转。** 直接对抱怨做 embedding 会召回同样出错的轨迹。所以模块 0 用 HyDE 生成"正确做法"的假设正例作为查询锚,再去召回。能力标签是"问题"和"轨迹签名"对齐的**唯一桥梁**——两端强制用同一份 Taxonomy、同一个映射 prompt,否则向量空间和标签空间都对不齐。

## ③ 四模块流水线:决策与权衡(约 95 秒)

**模块 0——查询编译。** 两次 LLM 调用:Call 1 拆原子子问题,Call 2 一次性产出能力标签、trajectory_signal、HyDE 正例、keywords、结构化过滤、以及置信度自评。**为什么置信度合进 Call 2**:评估维度全是 Call 2 的直接产出属性,不需要回看,省一次调用。低于 0.8 直接 drop,第一版不做澄清救回,保持管线简单。

**模块 1——离线处理与召回。** 两个关键决策:**其一,两层成本结构**——免费结构签名(语言/工具/报错/outcome_transition)全量离线抽,LLM 能力标签**惰性打标**,只在被召回时 batch 现打并缓存,把 LLM 调用从百万级压到每查询千级。**其二,分库**:结构化过滤是轨迹级、检索单位是切片级,粒度错位,所以 ES 负责过滤+BM25、Qdrant 只做 ANN、docstore 回溯原文。召回是向量+BM25+结构化过滤三路 RRF 融合。

**模块 2——相关性精排。** 第一版**砍掉了质量门和 learnability 门,只保留相关性单闸门**——因为上游数据来自更强模型且已过质量筛,质量门的过滤力极低,加了只会污染因果归因。核心改动是**软加分替代硬过滤**:命中标签 ×1.0,未命中 ×0.3 而非砍掉。理由是 LLM 打标签有噪声,召回分本身已保证语义相关,标签只做精修,不该让它一票否决。

**模块 3——集合优选,必须独立成模块。** 前面都在给单条打分,但 SFT 吃的是集合,直接取 top-N 会踩冗余、覆盖不均、配比失衡三个坑。用 **facility location submodular 贪心**:目标函数是每个子问题的覆盖度(带 cap_p 上限防堆积)加多样性项,配 min_per_problem 下限防饿死。递减收益特性天然同时解决覆盖均匀和多样性,保证 (1-1/e) 近似。全程零 LLM。

## ④ 演化与边界(约 30 秒)

**模块 0.5,标签系统演化——设计完成、尚未实现。** 它解决本体演化:新标签出现后,历史切片没打过会漏召回,而百万切片全量重打不可接受。方案是**继承降权 + 异步回填**:新标签即时挂树,查父标签的切片以 ×0.3 降权兜底(不断档);后台只对 keywords+description embedding 粗筛出的 1-5% 候选跑 LLM 精判,回填后升级为 ×1.0 精确命中。全程不阻塞查询。

**当前状态**:模块 0–3 已实现、测试通过、端到端跑通;0.5 是下一批。**因果归因是设计主线**——第一版刻意做成一个干净的"相关性检索系统",如果 SFT 有效,就证明检索假设成立;实验暴露的缺口(质量参差 / 相关但无增益)再决定第二版加哪个闸门。
